## Implemented contracts

### Pane focus and browser activation

- `WorkspaceContentsView::Present(..., InputCallbacks)` optionally accepts
  generation-bound focus, child-selection and resize requests. A standalone
  host with no callbacks remains display-only. Only the controller's explicit
  internal start path, requiring both OFF-by-default features, supplies input.
- Each committed leaf subscribes to its ContentsWebView, new-tab footer, actor
  overlay and reading-overlay focus callbacks. Reading focus must originate
  inside that leaf's reading overlay; other senders must be the current exact
  native view. The host checks drawing/window visibility, committed attachment,
  current container and weak page identity, and rejects presentation/clear-time
  callbacks. Subscriptions are refreshed with the committed generation and
  retired before deleting native hosts. Native renderer focus is observed
  explicitly: Views subtree suppression is NOT treated as native isolation.
- `RequestPaneFocus(TabKey, WeakPtr<WebContents>, generation)` checks active and
  visible window, current controller generation, live window/strip membership,
  actual contents and committed displayed attachment. It posts a non-nestable
  activation carrying the stable TabHandle and weak contents, then repeats
  these checks at dispatch. It never reveals a hidden page via renderer focus.
  A later accepted focus/header/resize or lifecycle change invalidates queued
  activation. Focus returning to the already-active pane cancels older input.
- Actual activation goes through Chromium's `ActivateTab` and the existing
  pre-observer foreground transaction. A weak-cleaned activation guard prevents
  native focus generated by deactivate/activate observers from replacing the
  in-flight request or erasing its structural-selection candidate.

### Headers and independent structural selection

- `RequestSelectChild(container, child, generation)` validates a currently
  presented header and immediate child, then posts non-nestable dispatch.
  Dispatch revalidates and uses `SetSelectedChild` on a candidate model, including
  ancestor reveal and remembered active descendant.
- If activation is necessary, the candidate is consumed only by the matching
  selection-only pre-observer lifecycle transaction, after Chromium selection
  changes. Thus browser activation, displayed/foreground policy and tree state
  share the existing commit seam. Structural selection remains the requested
  subtree rather than being overwritten with its active leaf. If the actual
  active tab is already correct, only structural/model presentation changes.
- Retained headers receive current callback epochs without recreating their
  stable child buttons. No tab ownership, global groups, session data or public
  shortcut dispatch was added.

### Common resize policy and native gesture lifetime

- `RequestResize(WorkspaceResizeRequest, generation)` is the common boundary
  for native cumulative pointer/touch requests and incremental divider key/AX
  requests. It validates a currently presented target and calls the existing
  geometry-authoritative `ResizeWorkspace` policy, retaining recursive minima,
  tree-order signs, RTL conversion and topology.
- The first cumulative request freezes model, target, viewport and metrics.
  Every later delta is applied to that same baseline, never accumulated against
  the last intermediate model. Keyboard/AX steps use current state and are
  rejected during a cumulative gesture. Completion discards the baseline.
- Weight-only commits preserve input generation and captured divider identity.
  Host presentation no longer rejects every live drag: retained captured
  surfaces keep target/conversion/range state and receive only committed value
  updates and new bounds. Normal Update resumes after completion. The controller
  announces values only after successful native/foreground publication, for
  pointer, keyboard and AX paths alike.
- `WorkspaceResizeArea::CancelResize` clears the base primitive's drag state
  without dispatching a synthetic completion. It latches cancellation until a
  fresh mouse press/touch tap-down, rejecting remaining movement from the old
  gesture even if callbacks were rebound. Native capture loss still completes
  at the last real cumulative displacement, not the base synthetic coordinate.
- Stop, strip topology/selection changes, confirmed detach, pre-detach and
  replacement revoke gestures and deferred requests. BrowserView window
  visibility/activation/bounds and device-scale notifications also revoke them.
  Every presentation independently detects changed viewport/scale/RTL before
  touching native geometry; in-flight validity checks include bounds and scale.
- Window/pre-lifecycle invalidation schedules a weak, generation-checked refresh
  outside the callback stack. This matters for canceled beforeunload: committed
  attachments remain, but input does not remain permanently bound to the revoked
  generation when no subsequent strip change occurs.

### Native-host focus routing

- BrowserView accessible-pane enumeration uses actual workspace leaf panes,
  headers and dividers, not detached ordinary-host slots.
- Stored-focus class mapping uses the committed active workspace container's
  page/footer/actor/reading views, with null/contents checks. The matching
  workspace active-tab UI commit now invokes this mapping and restores the
  destination's focus when appropriate. Already-landed native pane/accessory
  focus and header/divider keyboard/AX focus are preserved; inactive windows
  retain the normal deferred focus-restoration behavior.
- Deeper DevTools, modal/dialog, permission/find and fullscreen/accessory policy
  is explicitly left to T12, not declared solved by these focus routes.
